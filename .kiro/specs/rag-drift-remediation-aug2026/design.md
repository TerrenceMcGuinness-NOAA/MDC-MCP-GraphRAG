## Overview

No new code. This spec runs existing ingesters with verified arguments to close
the drift found in `Deep-Parity-Analysis-AWS-vs-COTS-2026-08-05`.

## Verified CLI surface (ground truth, 2026-08-05)

### Python v8 ingesters — `mcp_server_python/scripts/`

All share one parser:

```
--tenant TENANT              tenant id from tenants.yaml; omit → catalog default (gw)
--mode {diff,full}           default derived from tenant.lifecycle
--tiers [TIERS ...]          documentation script only
--dry-run                    print plan, write nothing
--delay DELAY                seconds between API calls
--only [ONLY ...]            restrict to named sources/files
--collection-version VER     target Collection_Version
```

`ingest_fortran_graph_v8.py` additionally accepts:

```
--workers WORKERS            parallel parse workers (default cpu_count-1)
--timeout TIMEOUT            per-file parse timeout, seconds (default 120)
```

**There is no `--model` flag.** The embedding profile is read from
`MCP_EMBEDDING_PROFILE`. **There is no `--fallback` flag** — see the Fortran
note below.

### URL crawling — `mcp_server_node/scripts/ingest_documentation_v8.py`

```
--tiers {tier1_critical,tier2_workflow,tier3_models,tier4_build,tier5_standards} [...]
--dry-run
--delay DELAY                seconds between page fetches (default 1.0)
--only ONLY [ONLY ...]
```

This is the crawler that owns the 51 `url_crawl` manifest sources. No `--model`;
profile via `MCP_EMBEDDING_PROFILE`.

**Important distinction:** `mcp_server_python/scripts/ingest_documentation_v8.py`
is *not* a crawler. It is 142 lines that walk the repo worktree through
`_ingest_walkers.files_for_full_branch` / `files_for_diff` — it ingests
repo-local documentation (the `on_disk_submodule` source type). Requirement 1
concerns stale **URL** crawls, so it is a Node-script operation.

### Benchmarks — `mcp_server_node/scripts/benchmark_runner.py`

```
usage: benchmark_runner.py [-h] [--models MODELS [...]]
                           [--search-modes {vector,hybrid,bm25} [...]]
                           ground_truth
```

`ground_truth` is a **required positional** argument. The file ships at
`mcp_server_node/scripts/config/benchmark_ground_truth.json`.

**Output caveat:** the runner uploads its report to S3
(`benchmark-reports/<timestamp>.json`) and renders markdown. It does **not**
write `quality_metrics.jsonl`, which is what `get_quality_metrics` reads. So a
successful benchmark run will *not* make `get_quality_metrics` stop saying "no
benchmark results found." That S3-to-JSONL wiring is a genuine, separate gap —
Requirement 5 is scoped to producing the report, not to lighting up the tool.

## Commands

### Task 1 — AWS URL re-crawl (run one tier at a time)

Five separate invocations rather than one, so a failure in one tier does not
cost the others and progress is checkpointable:

```bash
for TIER in tier1_critical tier2_workflow tier3_models tier4_build tier5_standards; do
  MCP_EMBEDDING_PROFILE=titan1024 DB_BACKEND=aws \
    python3.12 mcp_server_node/scripts/ingest_documentation_v8.py \
      --tiers "${TIER}" \
      --delay 1.0
done
```

Run a `--dry-run` on `tier1_critical` first to confirm source resolution.

- **Runtime**: 30-90 min per tier, 3-6 h total (51 sources, `max_pages` 20-250 each)
- **Risk**: low. Additive, SHA-deduped.
- **Verify**: `list_all_sources --include_gaps` shows `last_ingested` of
  `2026-08-05` for the tier's sources.

### Task 3 — AWS Fortran graph ingest

There is no `--fallback` flag because the regex fallback landed as
*unconditional* behaviour in `[8.33.0]` (`fortran-parse-fallback`, commit
`7c77ffd`) — the parser tries fparser2 and falls back on failure with no switch.
The COTS Neo4j numbers (80,745 `FortranSubroutine`) come from that code path;
Neptune's 27,941 predates it. So this is a plain re-run:

```bash
DB_BACKEND=aws \
  python3.12 mcp_server_python/scripts/ingest_fortran_graph_v8.py \
    --tenant gw \
    --mode full \
    --workers 8 \
    --timeout 180
```

- **Runtime**: ~3 h (Gap F recorded 6,926/6,935 files in ~3.2 h on the v17 tree)
- **Risk**: medium — writes nodes to Neptune. Merge-on-key, so re-runs are
  idempotent, but capture counts before and after.
- **Verify**: `get_knowledge_base_status` `FortranSubroutine` rises from 27,941
  toward the COTS figure (~80,745).
- **Escalation**: if the count does *not* move materially, the fallback is not
  in this script after all and Requirement 3 becomes a code-port spec rather
  than an ops task. Record the before/after numbers and stop.

### Task 6 — AWS quality baseline

```bash
DB_BACKEND=aws MCP_EMBEDDING_PROFILE=titan1024 \
  python3.12 mcp_server_node/scripts/benchmark_runner.py \
    mcp_server_node/scripts/config/benchmark_ground_truth.json \
    --search-modes vector hybrid bm25
```

- **Runtime**: 10-30 min
- **Risk**: none — read-only queries plus an S3 put
- **Verify**: markdown table printed; S3 object under `benchmark-reports/`
- **Known limitation**: `get_quality_metrics` still reports no results (see
  the output caveat above)

## Rollback

Ingestion is additive and SHA-deduped; successful runs need no rollback.

- **Vector**: delete the affected index and re-run.
- **Graph**: Fortran nodes from the fallback path carry a `parser` property;
  scope any cleanup with it rather than deleting by label alone.
