- 2026-07-15 (T2) — **improvement caught by Kiro, not in the original design**: `list_prestaged_paths` resolves `<owner>` to a numeric UID via `id -u` *before* invoking `find -not -uid`. A naïve `find -not -user "${owner}"` fails with `find: '<name>' is not the name of a known user` and produces silent empty output when the target user does not yet exist on the host — which is exactly the first-time-provisioning case (Anton pre-creation). Kiro's UID-first approach with a "user doesn't exist ⇒ owns nothing" fallback preserves the semantically correct pre-staged-path detection. Design.md was implicit on this; the implementation is now the ground truth.

- 2026-07-15 (T8-c) — **Clone-permission fix (Patch A)**. After T8-b's direct-clone flip, the operator (Terry) could not `git clone` into `${workspace_dir}/eib-mcp-rag-server` because `create_scratch_space()` had chown'd `${workspace_dir}` to `Anton:pwuser` mode 755. Fixed by having root pre-create `${repo_dir}` chown'd to `${SUDO_USER}` (`install -d -m 755 -o ${operator} -g pwuser`) so the operator has a writable target, then `chown -R ${username}:pwuser ${repo_dir}` at the end to hand the finished tree off. On failure the pre-created dir is `rmdir`'d so a subsequent re-run doesn't hit the "repo already exists" short-circuit.
- 2026-07-15 (T8-d) — **R5 pre-flight guard + create_user error propagation**. The R5 file-precedence branch already emitted `[ERROR] ... does not exist` and `return 1`, but the return code was ignored: `create_user()` called `resolve_initial_password` **after** `useradd` had already run, and `provision_user()` invoked `create_user` without checking exit status. Reordered `create_user()` so `resolve_initial_password` is called **before** `useradd` (any password-source failure aborts with zero mutation), added an explicit `if ! create_user ...; then return 1; fi` gate in `provision_user()`, and expanded the error message to name the three valid paths (file / TTY / generator). Smoke-test verified on a clean host: `PROVISION_INITIAL_PASSWORD_FILE=/tmp/does-not-exist bash 00-users.sh --user Anton.Fernando` → clean abort, no `useradd`, no `/home/Anton.Fernando`, no scratch mutation.
- 2026-07-15 (T8-e) — **Kiro-tool quoting hazard** (session-log note, no code change). Two AI-driven runs died to shell issues that had nothing to do with the script: (1) tempfile password generator using `!@#` character class triggered bash history expansion (`event not found`); (2) `PROVISION_INITIAL_PASSWORD_FILE="~/password.tmp"` did not expand `~` inside quotes. Neither is a script bug. Both were re-run cleanly once shell quoting was fixed. Lesson for future runs: use `A-Za-z0-9` only in AI-generated passwords, and prefer `$HOME/...` over `~/...` under sudo.
