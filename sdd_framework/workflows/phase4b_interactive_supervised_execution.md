# SDD: Phase 4B - Interactive Supervised Execution Mode

**Description**: Enable human-in-the-loop workflow execution with approval gates before side-effect steps. Designed to work across multiple CLI environments (VS Code MCP, Claude Code, terminal, GitHub Actions).

**Status**: PLANNING  
**Priority**: High  
**Prerequisite**: Phase 4 Bootstrap infrastructure (complete)  
**Date**: December 5, 2025

---

## 1. Problem Statement

The current SDD workflow executor has two modes:
- `dry_run: true` - Preview only, no side effects (SAFE)
- `dry_run: false` - Execute all steps autonomously (TOO RISKY)

**Gap**: No middle ground for supervised execution where humans approve each side-effect step.

## 4. Implementation Steps

### Step 1: Create ApprovalProvider Interface
**Type**: code_generation  
**Target**: mcp_server_node/src/sdd/approval/ApprovalProvider.js  
**Content**:
```javascript
/**
 * Abstract Approval Provider
 * Base class for different approval mechanisms
 */
export class ApprovalProvider {
  constructor(options = {}) {
    this.options = options;
    this.approvedAll = false;
  }

  /**
   * Check if step requires approval
   */
  requiresApproval(step) {
    // Side-effect steps require approval
    const sideEffectTypes = ['code_generation', 'code_modification', 'command', 'ingestion'];
    return sideEffectTypes.includes(step.type);
  }

  /**
   * Generate preview for step
   */
  generatePreview(step) {
    switch (step.type) {
      case 'code_generation':
        return {
          action: 'CREATE FILE',
          target: step.target,
          contentPreview: step.content?.substring(0, 500) + '...',
          contentLength: step.content?.length || 0
        };
      case 'code_modification':
        return {
          action: 'MODIFY FILE',
          target: step.file,
          modification: step.action
        };
      case 'command':
        return {
          action: 'RUN COMMAND',
          command: step.command,
          sandbox: step.sandbox !== false,
          timeout: step.timeout || 30000
        };
      case 'ingestion':
        return {
          action: 'UPDATE KNOWLEDGE BASE',
          target: step.target,
          source: step.source
        };
      default:
        return { action: step.type };
    }
  }

  /**
   * Request approval - must be implemented by subclasses
   */
  async requestApproval(step, preview) {
    throw new Error('requestApproval must be implemented');
  }
}

export const ApprovalResult = {
  APPROVED: 'approved',
  SKIPPED: 'skipped',
  QUIT: 'quit',
  APPROVE_ALL: 'approve_all'
};
```

### Step 5: Update WorkflowExecutor
**Type**: code_modification  
**File**: mcp_server_node/src/sdd/WorkflowExecutor.js  
**Action**: Add approval provider integration to executeStep()

```javascript
async executeStep(step, params) {
  // Check if approval required
  if (this.approvalProvider && this.approvalProvider.requiresApproval(step)) {
    const preview = this.approvalProvider.generatePreview(step);
    const approval = await this.approvalProvider.requestApproval(step, preview);
    
    switch (approval) {
      case ApprovalResult.SKIPPED:
        return { name: step.name, status: 'skipped', reason: 'User skipped' };
      case ApprovalResult.QUIT:
        throw new Error('Workflow aborted by user');
      case ApprovalResult.APPROVE_ALL:
        this.approvalProvider.approvedAll = true;
        break;
      // APPROVED falls through to execute
    }
  }
  
  // Execute step...
}
```

## 6. CLI Interface (Claude Code / Terminal)

### Command Line Usage

```bash
# Interactive supervised execution
$ npx mcp-workflow execute bootstrap_capability_demo --supervised

# Auto-approve read-only steps
$ npx mcp-workflow execute data_ingestion \
    --supervised \
    --auto-approve health_check,validation,data_query

# Use approval manifest
$ npx mcp-workflow execute ee2_compliance_scan \
    --approval-manifest ./approvals.json

# Dry run (preview only)
$ npx mcp-workflow execute bootstrap_capability_demo --dry-run
```

```json
{
  "version": "1.0",

  "auto_approve": [

    { "step_type": "ingestion" }

  "deny": [
    { "step_type": "command", "pattern": "rm.*" }
```

## 7. Validation

### Test Cases

1. **MCP Multi-Turn**: Execute supervised workflow via VS Code Copilot, approve each step
2. **CLI Interactive**: Run in terminal, use keyboard prompts
3. **Manifest Auto-Approve**: Pre-approve read-only steps, manual approve side effects
4. **Abort Mid-Workflow**: User quits, verify no partial state
5. **Skip Step**: User skips code_generation, verify workflow continues
6. **Approve All**: User approves remaining steps in batch

### Acceptance Criteria

- [ ] MCP tool pauses and returns pending state for side-effect steps
- [ ] Multi-turn conversation resumes execution correctly
- [ ] CLI readline prompts work in terminal
- [ ] Manifest file pre-approves matching step types
- [ ] User can skip individual steps without aborting
- [ ] User can quit and workflow cleans up gracefully
- [ ] Approve-all completes remaining steps without prompts
- [ ] Execution history records approval decisions

## 8. Security Considerations

1. **Execution ID Validation**: Prevent replay attacks by expiring execution IDs
2. **Approval Timeout**: Auto-abort if no approval within configurable timeout (default: 5 min)
3. **Audit Trail**: Log all approval decisions with timestamp and user context
4. **Manifest Signing**: Optional cryptographic signing for approval manifests in CI/CD
