create) one IAM OIDC identity provider and three IAM roles. The PowerUser

account is `ncis-gitlab.nesdis-hq.noaa.gov` — the GitHub Actions provider is

5. One-time: populate the CI client secret value  (Correction C12)
------------------------------------------------------------------

The CDK stack creates the Secrets Manager secret
`mdc-mcp-external-access-alt/ci-app-client` as a RETAIN shell containing the
(non-secret) `client_id` and a `client_secret` placeholder. CDK does NOT pull
the real client secret through CloudFormation, because doing so injects a
`Custom::DescribeCognitoUserPoolClient` resource whose auto-created Lambda role
needs `iam:CreateRole` (blocked for PowerUser, C7). After `cdk deploy`, inject
the real client secret once:

    CLIENT_ID=$(aws cognito-idp describe-user-pool \
      --user-pool-id <HpcUserPoolId output> --region us-east-1 >/dev/null; \
      aws cloudformation describe-stacks --stack-name MdcExternalAccessAlternativeStack \
        --query "Stacks[0].Outputs[?OutputKey=='CiAppClientId'].OutputValue" --output text)
    CLIENT_SECRET=$(aws cognito-idp describe-user-pool-client \
      --user-pool-id <HpcUserPoolId output> --client-id "$CLIENT_ID" \
      --query 'UserPoolClient.ClientSecret' --output text --region us-east-1)
    aws secretsmanager put-secret-value \
      --secret-id mdc-mcp-external-access-alt/ci-app-client \
      --secret-string "{\"client_id\":\"$CLIENT_ID\",\"client_secret\":\"$CLIENT_SECRET\"}" \
      --region us-east-1

This keeps the client secret out of CloudFormation state entirely.
