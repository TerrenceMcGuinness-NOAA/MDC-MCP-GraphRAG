REQUEST
-------

Please update ONE condition value in an existing group policy to add
"us-east-2" to the list of allowed regions. This unblocks cross-region
inference profiles for all PowerUser group members. No new policies,
roles, or resources are created.


BACKGROUND
----------

All modern Bedrock generative models (Claude Opus 5, Sonnet 5, Nova,
etc.) REQUIRE invocation via inference profiles. Inference profiles
with a "us." prefix route requests across us-east-1 AND us-east-2 for
availability and load balancing. The current group policy denies ALL
API calls outside us-east-1, which blocks every inference profile
invocation even when MFA is present.

This is not a workaround — it is the only supported invocation path
for these models. Direct model-ID invocation returns
"ValidationException: Invocation of model ID ... with on-demand
throughput isn't supported. Retry your request with the ID or ARN of
an inference profile."

WHY THIS IS NEEDED
------------------

All modern Bedrock generative models (every Claude and Nova model
released after Claude 3 Haiku, March 2024) support ONLY inference
profile invocation — not direct model-ID on-demand. Inference profiles
with a "us." prefix distribute requests across US regions for
availability.

The current policy (v2) allows ONLY us-east-1, blocking every
inference profile call. This means:

  - Developers CANNOT test generative model calls from the EC2 host
  - The benchmark runner CANNOT score generative-model cases
  - VS Code Bedrock extensions CANNOT connect to Claude
  - Gap J community-summaries script CANNOT run from the dev host
  - ANY new development requiring Claude access is blocked

The Titan embedding model works today ONLY because it supports direct
model-ID invocation (not inference profiles) and stays in us-east-1.
This is legacy behavior — future Titan versions may also require
inference profiles.


WHY THIS REQUIRES ADMIN
------------------------

The PowerUser group policy does not allow iam:CreatePolicyVersion on
customer-managed policies. Verified August 27, 2026:

    AccessDenied: User arn:aws:iam::903050880929:user/terry.mcguinness@noaa.gov
    is not authorized to perform: iam:CreatePolicyVersion on resource:
    policy MFA-self-management-withoutCLIEnforcement


WHAT THIS CHANGES
-----------------

ONE condition value in ONE statement of ONE existing policy:

  Policy: MFA-self-management-withoutCLIEnforcement
  Statement: DenyAllOutsideRequestedRegions
  Field: Condition.StringNotEquals.aws:RequestedRegion
  Change: "us-east-1" → ["us-east-1", "us-east-2"]

Everything else — all 6 other statements, the MFA enforcement logic,
the NotAction lists — remains byte-for-byte identical.


WHAT THIS DOES NOT DO
---------------------

  - Does NOT disable MFA enforcement (the MFA deny is unchanged)
  - Does NOT open any new AWS service in us-east-2 (only Bedrock
    inference profile routing uses us-east-2; no resources are created
    there)
  - Does NOT affect the us-east-1 restriction for non-Bedrock services
  - Does NOT modify any IAM roles, users, or other policies
  - Does NOT create any new resources in us-east-2
  - Does NOT affect the AgentCore runtime role (it has no region lock)
  - Does NOT grant access to any new AWS service


SECURITY SCOPE
--------------

The change permits API calls to us-east-2 IN ADDITION TO us-east-1.
However:

  - MFA is STILL required for all actions (the BlockMostAccess deny is
    unchanged)
  - The only service that routes to us-east-2 today is Bedrock
    inference profiles — no other AWS service in this account has
    resources in us-east-2
  - PowerUserAccess already has no service-level restrictions, so the
    region is the only additional surface opened
  - All API calls remain logged in CloudTrail regardless of region

Risk assessment: LOW. The region deny was a coarse governance control
to prevent accidental resource creation in unexpected regions. Adding
us-east-2 for Bedrock inference routing does not create resources — it
only permits read-time API calls to the Bedrock service endpoint in
that region.


IMPACT
------

  - Affects all members of the PowerUser group (currently: 1 user)
  - Takes effect immediately, no restart required
  - Zero downtime, zero cost impact (no new resources created)
  - Still requires MFA for all non-whitelisted actions
  - Reversible by creating a new policy version restoring the original
    condition:
