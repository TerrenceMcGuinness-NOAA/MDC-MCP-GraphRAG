REQUEST
-------

Please attach an existing IAM role to an existing Neptune cluster so
that Neptune's native bulk loader can read data files from S3. This is
a single CLI command — no new resources are created.


COMMAND TO RUN
--------------

    aws neptune add-role-to-db-cluster \
      --db-cluster-identifier mdc-mcp-rag-neptune \
      --role-arn arn:aws:iam::903050880929:role/service-role/mdc-mcp-rag-neptune-s3-loader \
      --region us-east-1

-----------------------

    aws neptune describe-db-clusters \
      --db-cluster-identifier mdc-mcp-rag-neptune \
      --query 'DBClusters[0].AssociatedRoles' \
      --region us-east-1

Expected output: one entry with RoleArn and Status "ACTIVE".

WHAT THIS ENABLES
-----------------

Neptune's native bulk loader API (/loader endpoint) can read openCypher
CSV files directly from S3 using Neptune's internal parallel loading
engine. This is 10-100x faster than loading via Bolt protocol and avoids
SigV4 token expiry issues that caused our previous load attempts to fail.

We need to load:
  - 98,813 graph nodes
  - 2,633,374 graph relationships

The Bolt-based approach failed silently on all 2.6M relationships due to
query timeouts and error handling issues. The bulk loader bypasses these
problems entirely.


WHAT THIS DOES NOT DO
---------------------

  - Does NOT create any new IAM roles or policies
  - Does NOT create any new AWS resources
  - Does NOT modify Neptune configuration or capacity
  - Does NOT expose any services to the internet
  - Does NOT affect other users or workloads in the account
  - Does NOT grant the role any permissions beyond S3 read on one bucket


SECURITY SCOPE
--------------

The role has minimal permissions — read-only access to a single S3 bucket:

    {
      "Effect": "Allow",
      "Action": ["s3:GetObject", "s3:ListBucket"],
      "Resource": [
        "arn:aws:s3:::mdc-mcp-rag-migration",
        "arn:aws:s3:::mdc-mcp-rag-migration/*"
      ]
    }

The role can only be assumed by rds.amazonaws.com (Neptune's service
principal). It cannot be assumed by users, EC2 instances, or Lambda.
