SUMMARY
-------

The CDK bootstrap completed successfully (thank you!), but the
CloudFormation execution role was provisioned with PowerUserAccess
+ PowerUserRestrictions instead of the standard AdministratorAccess.
This prevents CloudFormation from creating IAM service roles that
our CDK stacks need (ECS task roles, etc.).

This is NOT a request to change our user permissions. This is about
the CloudFormation execution role that CDK uses internally.


THE PROBLEM
-----------

Role: cdk-hnb659fds-cfn-exec-role-903050880929-us-east-1

Currently attached policies:
  1. PowerUserAccess (AWS managed)
  2. PowerUserRestrictions (account policy — denies iam:CreateRole)

When CDK deploys a stack, CloudFormation assumes this role to create
resources. Our stacks need CloudFormation to create IAM service roles
for ECS tasks (standard AWS pattern). The PowerUserRestrictions policy
blocks this with:

  "User: arn:aws:sts::903050880929:assumed-role/
   cdk-hnb659fds-cfn-exec-role-903050880929-us-east-1/AWSCloudFormation
   is not authorized to perform: iam:CreateRole"


THE FIX (Option A — Recommended)
---------------------------------

Replace the current policies on the CDK execution role with the
standard AdministratorAccess policy. This is the default CDK bootstrap
configuration per AWS documentation.

Commands:

  aws iam detach-role-policy \
    --role-name cdk-hnb659fds-cfn-exec-role-903050880929-us-east-1 \
    --policy-arn arn:aws:iam::903050880929:policy/PowerUserRestrictions

  aws iam detach-role-policy \
    --role-name cdk-hnb659fds-cfn-exec-role-903050880929-us-east-1 \
    --policy-arn arn:aws:iam::aws:policy/PowerUserAccess

  aws iam attach-role-policy \
    --role-name cdk-hnb659fds-cfn-exec-role-903050880929-us-east-1 \
    --policy-arn arn:aws:iam::aws:policy/AdministratorAccess

Reference: https://docs.aws.amazon.com/cdk/v2/guide/bootstrapping.html
  "By default, the CloudFormation execution role has AdministratorAccess"

CONTEXT
-------

The CDK execution role is an internal role that CloudFormation assumes
when deploying stacks. It is not used by any user directly. The
standard CDK bootstrap gives this role AdministratorAccess because
CloudFormation needs to create whatever resources the stack defines,
including IAM service roles for ECS, Lambda, etc.

The PowerUserRestrictions policy was likely applied to this role by
the bootstrap process inheriting the caller's policies. This is not
the intended configuration.


IMPACT OF THE FIX
-----------------

  - Unblocks all CDK stack deployments for this project
  - No impact on user permissions or other workloads
  - Standard AWS CDK configuration per documentation
  - The role is only assumable by cloudformation.amazonaws.com
