REQUEST
-------

Please add one route table to an existing S3 VPC Gateway endpoint so
that Neptune can reach S3 for bulk loading. Single CLI command.


COMMAND TO RUN
--------------

    aws ec2 modify-vpc-endpoint \
      --vpc-endpoint-id vpce-0ab581c681d867664 \
      --add-route-table-ids rtb-03e894efb9a5095de \
      --region us-east-1


VERIFICATION
------------

    aws ec2 describe-vpc-endpoints \
      --vpc-endpoint-ids vpce-0ab581c681d867664 \
      --query 'VpcEndpoints[0].RouteTableIds' \
      --region us-east-1

Expected: should now include both rtb-0ab852fa2c13b1a06 AND rtb-03e894efb9a5095de


WHY THIS IS NEEDED
------------------

Neptune's bulk loader API reads data directly from S3. Neptune is in
private subnets (nihacio-nwspocaisofteng-PrivateSubnet1/2/3) which use
route table rtb-03e894efb9a5095de. The S3 Gateway endpoint
(vpce-0ab581c681d867664) is currently only associated with route table
rtb-0ab852fa2c13b1a06 (the DO-NOT-USE subnets).

Neptune returns: "Unable to connect to s3 endpoint"

Adding Neptune's route table to the S3 endpoint fixes this.


WHY THIS REQUIRES ADMIN
------------------------

PowerUserRestrictions policy explicitly denies ec2:ModifyVpcEndpoint.


WHAT THIS DOES NOT DO
---------------------

  - Does NOT create any new VPC endpoints or resources
  - Does NOT modify any security groups or NACLs
  - Does NOT change any subnet configurations
  - Does NOT affect the existing route table association
  - Does NOT expose any services to the internet


IMPACT
------

  - Adds one route table association to an existing S3 Gateway endpoint
  - No downtime, takes effect immediately
  - Zero cost impact
  - Existing S3 access from the DO-NOT-USE subnets is unaffected
